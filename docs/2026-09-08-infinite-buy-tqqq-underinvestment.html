2. 원인 ① — floor 절삭. 매 회차 $55씩 주문조차 되지 않음

strategy-v22.ts의 1회 매수금은 daily = principal / splits = 8000 / 40 = $200 고정입니다. 이걸 두 트랜치로 쪼갠 뒤 주식 수량을 Math.floor로 내림합니다.

const qAvg = Math.floor(half / s.avgPrice);      // half = $100
const qVar = Math.floor(half / bigPrice);
구간트랜치배정 예산단가실제 주문미집행
전반전 (T<20)loc_avg$100$72.581주 = $72.58$27.42
loc_var$100$72.941주 = $72.94$27.06
후반전 (T≥20)loc_var 단일$200$71.992주 = $143.98$56.02

즉 설계상 $200 중 최대 $144(72%)만 주문되고 나머지 $56은 그냥 버려집니다. 잔여 예산을 다음 회차로 넘기는 이월(carry-over) 로직이 없어서, 이 손실이 매 거래일 반복됩니다. 주문 이력의 수량이 22회차 내내 전부 1주(9/03부터 2주)인 게 정확히 이 현상입니다.

원금의 약 26%($2,100)는 사이클이 끝날 때까지 구조적으로 사용되지 않습니다. TQQQ 주가가 오를수록 1주 단가가 커져 이 비율은 더 악화됩니다.

3. 원인 ② — LOC 미체결 8주

주문 44주 vs 보유 36주. LOC(종가 지정가) 매수는 종가가 지정가 이하일 때만 체결되므로, 8월 중순 반등 구간에서 loc_avg(평단가 매수)가 여러 번 미체결된 것으로 보입니다. 이건 전략상 정상 동작이지만, 회차(T)는 체결 여부와 무관하게 매 실행마다 +1 되기 때문에 (run.ts: nextRound = s.round + 1) 미체결분만큼 원금이 남은 채 회차만 소진됩니다.

4. 수치의 신뢰도에 관한 단서

현 사이클의 주문은 전부 status=submitted이고 filled_qty가 비어 있습니다. v2.2 실행 경로는 체결 동기화를 자동 호출하지 않기 때문입니다(syncFillsFromToss는 v4.0과 UI 버튼 전용). 위의 "보유 36주 · 평단 $72.35"는 9/04 매도 주문 수량에서 역산한 값이라 실제 토스 잔고와 일치할 가능성이 높지만, 확정하려면 화면의 "토스 체결 동기화" 버튼을 누르거나 토스 앱에서 직접 확인하세요.

5. 개선 옵션

안내용효과비용 / 리스크
A. 잔금 기반 회차금액
(권장)		 daily = (principal − 보유×평단) / (splits − round)
v4.0의 perBuy = cash/(분할−T) 방식을 v2.2에 이식. 보유·평단은 토스 스냅샷에 이미 있어 새 상태 필드 불필요.		 절삭·미체결로 남은 돈이 남은 회차에 자동 재분배 → 40회차에 원금 100% 소진. 현 시점 적용 시 회차금액 $200 → $299(잔금 5,395 ÷ 18회차), 주문 2주 → 4주. strategy-v22.ts 수정 + 테스트. 진행 중 사이클에 적용하면 매수액이 즉시 2배가 되므로 새 사이클부터 적용할지 결정 필요.
B. v4.0 전환 이미 구현된 v4.0은 잔금·연속 T를 추적해 이 문제가 없음. 근본 해결 + 별% 규칙까지 최신화. 현재 v4.0은 LIVE 미지원(infinite-buy.ts:275 — dryRun 검증 전용). 실전 투입하려면 별도 작업 필요.
C. 설정만 조정 splits를 40 → 20 등으로 축소. 회차당 금액이 커져 절삭 비율만 하락(27% → 14%). 코드 수정 0. 40분할이라는 무한매수법 규칙 자체가 바뀜. 근본 해결 아님.
D. 유지 현 상태 그대로. — 원금의 26%가 계속 유휴. 사이클마다 반복.
