동작

계좌·종목·차수별 전략과 함께 감시 가격 및 유효일을 저장한다. 생성 직후에는 정지 상태이며 상세 화면에서 시작을 확인한다. 거래 가능한 시간의 유효 시세가 감시 가격 이하이면 1차 지정가 주문을 생성하고 실제 체결 후 기존 분할매매를 이어간다. 유효일은 한국시간 날짜 끝까지이고, 최초 진입 뒤에는 재적용하지 않는다.

저장·검증양수 가격, 유효한 오늘 이후 날짜, 기존 예산·차수 검증, 계좌·종목 소유권 유지
감시·주문가격 미도달 시 주문 없음, 주문 의도·예약 상태의 원자적 저장, lease·revision·시장 시간·시세 유효성 재사용
체결·실패접수와 실제 체결 구분, 부분 체결 중복 반영 방지, 접수 미확인 자동 재전송 금지, 미체결 종료 후 명시적 조건 재저장
관리 화면감시 현황·실행·실패 및 만료·전체 이력, 종목 검색, 상세 설정 연결, 30초 갱신. 각 이력 탭 최근 200건

검증 근거

최종 전체 테스트: 69개 파일, 662개 테스트 통과.

기존 코드에서는 감시 가격보다 높은 시세에서도 주문하는 테스트 실패를 먼저 확인했다. 임시 SQLite DB를 이용해 가격 도달, 한국시간 만료, 유효한 lease 중 만료, HTTP 전송 기한, 부분 체결, 접수 불명·대조, 취소 후 재개, 자금 부족, 잘못된 입력, 실제 체결 후 2차 진입 및 이력 조회를 검증했다.

타입 검사와 변경 파일 ESLint를 통과했다. AppMenu에는 기존 react-hooks/set-state-in-effect 오류가 있어 해당 기존 규칙만 제외한 검사도 별도로 수행했다. 초기 전체 테스트에서 샌드박스 loopback 제한으로 실패한 3개는 임시 포트 허용 환경에서 통과했다. 브라우저에서는 데스크톱·390px 모바일·다크모드의 빈 목록, 내역 탭, 예약 등록 진입을 확인했다. 실제 주문은 제출하지 않았으며 테스트용 예약을 실제 DB에 만들지 않았다.

검토

독립 소스 검토에서 차단 수준의 결함은 발견되지 않았다. 기존 작업이 대량의 untracked 파일로 남아 있어 분리된 Git 기준점이 필요한 정식 리뷰 파이프라인은 완료하지 못했고, 예약 기능의 명시적 파일 범위에 대한 수동 소스 검토로 대체했다. 반영 상태

DB 백업 후 새 테이블 두 개를 추가하는 migration을 적용하고 Prisma Client를 생성했다. 개발 서버는 새 모델을 읽도록 재시작되어 예약 화면을 제공한다. 기존 실거래 전략·주문 데이터는 변경하지 않았다.

워커 재시작은 승인 대기다. 기존 워커는 SIGTERM을 받아 신규 분할매매 감시를 중지했으나 다른 루프 때문에 프로세스가 남아 있다. 자동 승인 검토가 두 PID의 강제 종료 및 새 실거래 워커 시작을 거부했다. 승인 후 단일 인스턴스로 재시작해야 예약 감시와 기존 자동매매가 동작한다.
