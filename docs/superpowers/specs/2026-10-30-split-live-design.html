분할매매 자동 실거래 설계

2026-10-30 · company-map · 설계 확인용

사용자가 확정한 요구: 기존 토스 연동을 재사용해 분할매매 실거래를 추가한다. 사용자가 시작한 전략을 워커가 감시하고, 조건을 충족하면 자동으로 주문한다.

아래의 주기·주문 방식·정규장 범위 등은 구현자가 제안하는 첫 버전의 결정이다. 아직 사용자가 확인한 조건으로 취급하지 않는다.

사용 흐름

  1. 공통 메뉴의 분할매매 모의 장부를 분할매매로 바꾸고, 같은 화면에 모의·실거래 장부를 구분해 보여준다. 기존 모의 기능과 기록은 유지한다.
  2. 실거래 전략 만들기에서 토스 계좌, 국내/미국 종목, 배정 자금, 차수당 예산, 최대 차수, 하락 간격, 익절률, 비용 여유율을 설정한다. KRW/USD는 전략의 고정 통화이며 자동 환전하지 않는다.
  3. 전략은 정지 상태로 만든다. 실계좌와 설정을 확인한 뒤 자동매매 시작을 누르면 정규장 중 첫 유효 시세에서 1차 매수를 주문한다. 장이 닫혔으면 다음 정규장까지 기다린다.
  4. 워커가 주문 상태와 실제 누적 체결을 읽어 차수 원가·잔량·손익·배정 잔액을 갱신한다. 화면에는 마지막 감시 시각, 다음 조건, 보류 사유, 주문번호와 부분 체결 상태를 표시한다.
  5. 일시정지는 신규 주문만 멈춘다. 이미 제출된 주문은 계속 체결될 수 있으며, 상태 동기화는 계속한다. 미체결 취소·정정은 첫 버전에서 토스 앱으로 처리하고 화면에 이 동작을 명확히 안내한다.

자동 매매 규칙

항목 첫 버전 제안
시장·수량 국내 및 미국 주식, 정수주. 계좌와 시장·통화가 맞는지 검증한다. 시작 시 기존 보유가 없는 종목을 사용하며 다른 장부의 보유를 가져오지 않는다.
감시 독립 worker 루프에서 30초 주기로 확인한다. REST 폴링이므로 순간적인 가격 통과를 모두 잡지는 못한다. 조회 한도에 맞춰 순차 처리하고 오류 시 간격을 늘린다.
세션·시세 토스 캘린더로 확인한 정규장에서만 신규 주문한다. 시세가 60초보다 오래되거나 미래 시각·비정상 값이면 주문하지 않는다. 일시정지·장 마감 후에도 제출된 주문은 조회·정산한다.
주문 방식 정수 수량의 지정가 DAY 주문. 해당 관측 시세를 기준으로 호가 단위에 맞춘다. 매수가는 내림, 매도가는 올림한다. 미국은 1달러 이상 2자리, 미만 4자리 규칙을 적용한다. 국내 호가 규칙은 종목 유형을 확인해 적용하고 판단 불가 시 보류한다. 시장가 추격·자동 정정은 하지 않는다.
매수 1차는 시작 후 첫 관측. 이후에는 보유 중인 직전 차수의 실제 평균 매수가 대비 설정 하락률로 판단한다. 차수 예산에는 비용 여유액을 포함하며 배정 잔액과 실제 주문 가능 금액 양쪽을 확인한다.
매도·재진입 차수별 실제 평균 매수가 대비 익절률로 판단한다. 매도 조건을 우선하며 여러 차수가 동시에 도달하면 높은 차수부터 처리한다. 청산한 차수는 직전 차수가 보유 중이고 매수 조건을 다시 충족할 때 새 회차로 진입한다.
미체결 전략별 미해결 주문은 한 건만 허용한다. 부분 체결이 있어도 주문이 끝나기 전에는 다음 주문을 내지 않는다. DAY 미체결은 시간 경과만으로 취소됐다고 추정하지 않고 브로커 상태를 확인한다.
전량 청산 실제 매수 이력이 있고 모든 차수가 청산되면 종료한다. 자동으로 1차 매수를 반복하지 않는다. 새 사이클은 새 전략으로 시작한다.
거절·불명확 결과 확실한 주문 거절은 사유와 함께 자동매매를 일시정지한다. 타임아웃·전송 후 DB 저장 실패·알 수 없는 주문 상태는 결과 미확인으로 보존하고 신규 주문을 막는다. 자동으로 같은 주문을 재전송하지 않는다.
기존 주문·외부 변경 같은 계좌·종목의 다른 앱 전략 및 미체결 주문이 있으면 시작·신규 주문을 막는다. 수동 매매 등으로 실제 보유와 장부 잔량이 달라지면 자동 정지한다. 기존 보유와 섞어 운용하는 기능은 제외한다.

실제 체결과 장부

  • 모의 장부의 dryRun을 바꿔 사용하지 않는다. 별도의 실거래 전략·차수·주문 테이블을 두고 계좌번호 대신 고정 accountSeq로 연결한다.
  • 주문 제출 전 DB에 주문 의도와 영구 고유 키를 먼저 기록한다. 차수·회차·주문 순번으로 중복 의도를 차단하고, 토스 요청에도 36자 이하의 고유 clientOrderId를 보낸다. 브로커 멱등키의 10분 유효기간에 재전송 안전성을 의존하지 않는다.
  • 차수별로 주문의 누적 체결 수량·금액·수수료·세금을 이전 누적값과 비교해 차이만 반영한다. 잔량·원가·배정 잔액·실현손익의 변경과 체결 반영 표시는 하나의 DB 트랜잭션으로 저장한다.
  • 부분 매수 후 취소되면 실제 매수분만 보유로 남긴다. 부분 매도 후 취소되면 실제 매도분의 원가와 손익만 정산하고 잔량을 유지한다. 실제 원가와 수수료·세금으로 계산하며 모의 실행에 입력한 비용을 실제 비용처럼 쓰지 않는다.
  • 체결 수량·금액·비용의 누락, 누적 체결의 감소, 수량 초과, 다른 종목·방향·통화 응답은 불일치로 보류한다. null 비용은 확정 0으로 간주하지 않고 미확정으로 표시한다. 필요한 값이 확인되기 전에는 다음 주문을 막는다.
  • 실거래 잔액은 계좌 전체 예수금이 아니라 해당 전략에 배정한 자금에서 실제 체결 비용을 차감한 값이다. 실제 주문 가능 금액을 매번 함께 확인하며 다른 종목을 위해 예수금을 예약하는 기능은 제공하지 않는다.

동시 실행·장애 복구

  • DB에서 계좌·종목 소유권과 전략 실행 잠금을 관리한다. 잠금 만료 전 복수 worker가 같은 주문을 제출할 수 없도록 조건부 갱신을 사용한다. 네트워크 왕복 중에는 DB 트랜잭션을 열어두지 않는다.
  • 접수된 주문은 목록 첫 페이지 대신 GET /api/v1/orders/{orderId}로 추적한다. 재기동 후에도 미해결 주문을 먼저 조회한다. 알 수 없는 상태는 완료로 처리하지 않는다.
  • 주문번호를 받기 전에 전송 결과가 불명확해지면 자동 정지한다. 사용자가 토스에서 확인한 주문번호를 입력하면 계좌·종목·방향·수량·가격·시각을 검증해 연결하고, 연결된 주문을 다시 보내지 않는다. 미접수가 확인된 경우에만 명시적 확인으로 의도를 닫고 재개한다.
  • 토스에서 수동 정정한 주문의 연결 관계를 확인할 수 없으면 자동 정지한다. 수동 취소의 부분 체결은 주문 상세로 정산한다. 미확인 행을 삭제해 잠금을 푸는 기능은 만들지 않는다.
  • SPLIT_LIVE_DISABLED=1이면 신규 실주문을 차단한다. 주문 동기화는 계속한다. 환경 변수의 실제 값이나 자격증명은 문서·로그·테스트 출력에 담지 않는다.
  • 화면에 worker 최근 감시 시각을 표시한다. worker가 실행되지 않으면 자동매매도 진행되지 않는다는 점을 표시한다. 구현 확인을 위해 실제 운영 worker를 재시작하거나 실거래 전략을 시작하지 않는다.

검증과 완료 기준

  1. 가짜 브로커와 임시 SQLite에서 최초 매수, 다차수 진입, 차수별 익절, 재진입, 전량 청산, 부분 체결·부분 취소·수수료 정정을 재현한다.
  2. 별도 Prisma 클라이언트 두 개의 동시 실행, 제출 전후 프로세스 중단, 타임아웃 후 재기동, 같은 체결 반복 조회에서 주문 중복과 장부 이중 반영이 없음을 확인한다.
  3. 장 마감·휴장·오래된 시세·예수금 부족·외부 주문·보유 불일치·킬스위치에서 신규 주문이 0건인지 검증한다.
  4. 계좌·가격·수량·통화 불일치, null 비용, 모르는 주문 상태, 다른 전략 충돌과 미확인 주문 복구를 검증한다.
  5. 전체 테스트·타입 검사·변경 파일 lint와 브라우저 검증을 수행한다. 개발 중에는 브로커를 모킹하고 실제 주문·전략 시작·LIVE 활성화를 실행하지 않는다. 실제 시장 접수는 사용자가 계좌와 자금을 정해 시작한 뒤 확인할 단계다.

조건주문·WebSocket 전환, 시간외 매매, 소수점 매매, 자동 환전, 기존 보유 가져오기, 리스플릿·수익부스터, 자동 가격 추격·정정, 앱에서 미체결 취소, 자동 손절·강제 청산은 추가하지 않는다. 1억원 이상 주문 확인 플래그를 자동으로 켜지 않으며 해당 규모 주문은 보류한다.
