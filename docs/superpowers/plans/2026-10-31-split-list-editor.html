분할매매 목록과 편집 화면 분리

종목이 많아도 목록을 빠르게 확인하고, 등록·수정은 독립 화면에서 처리한다. 기존 저장·자동매매 동작과 장부는 유지한다.

화면

  • /stocks/split: 실거래·모의 목록 탭, 전체 누적 수익금, 검색·시장·상태 필터, 종목명 오름차순 정렬, 스크롤 하단에서 20개씩 추가 표시. 종목별 상태·보유수량·누적 수익금·총손익·최근 감시를 표시한다.
  • /stocks/split/new?mode=live 또는 simulation: 해당 종류의 등록 폼만 표시. 저장 성공 후 생성한 전략 상세로 이동한다.
  • /stocks/split/live/[id]: 선택한 실거래의 설정 수정·시작/정지·동기화·체결 장부.
  • /stocks/split/simulation/[id]: 선택한 모의 전략의 가격 입력·상태·장부.

구현

기존 LiveManager·SplitManager에 create/detail 모드를 명시하고 목록에서는 사용하지 않는다. 목록으로 차수별 폼과 주문 이력을 전달하지 않는다. 상세 조회는 id로 제한하며 없는 ID는 404를 표시한다. 생성 액션은 생성 ID를 반환하고 하위 경로 캐시도 갱신한다. 공통 메뉴에 종목 목록·등록·관심종목 링크를 둔다.

검증

  1. 검색·필터·종목명 정렬와 생성 액션의 ID 반환을 테스트한다.
  2. 목록에 편집 입력이 없고 상세에 단일 전략만 나오는지, 등록 폼·존재하지 않는 ID·뒤로가기·모바일을 브라우저로 확인한다.
  3. 관련 테스트·타입·린트를 실행하고 실제 전략 값·주문을 변경하지 않는다. DB 마이그레이션과 자동 커밋은 없다.

완료 확인

2026-10-31: 전체 Vitest 63개 파일·624개 테스트, TypeScript 검사, 변경한 코드의 ESLint 검사를 통과했다. 브라우저에서 실거래 4개·모의 1개 목록, 검색·상태 필터, 등록 화면 이동, 선택한 전략만 나오는 상세, 뒤로가기, 없는 ID의 404를 확인했다. 390px 모바일에서 가로 넘침이 없고 데스크톱 목록 배치를 확인했다. 생성 성공·실패의 ID 반환과 상세 조회 범위는 모의 의존성 테스트로 검증했으며 실제 전략 생성·설정 저장·주문은 실행하지 않았다. 별도 코드 검토에서 수정이 필요한 회귀는 발견되지 않았다.

목록 탐색 변경 검증

2026-10-31 후속 요청: 페이지 버튼을 제거하고 종목명순 무한 스크롤로 변경했다. 검색·필터 변경 시 표시 범위를 초기화한다. 정렬·검색 단위 테스트 2개와 TypeScript·변경 코드 ESLint 검사를 통과했다. 실제 화면의 종목명 정렬·페이지 버튼 제거를 확인했고, 실제 컴포넌트에 가상 종목 45개를 전달한 별도 브라우저 검사에서 20→40→45개 누적 표시, 중복 없음, 검색 해제 후 20개 초기화를 확인했다. 검증용 파일은 제거했으며 실제 전략 데이터는 변경하지 않았다.
