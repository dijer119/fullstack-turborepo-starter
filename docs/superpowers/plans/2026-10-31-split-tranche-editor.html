차수별 자동매매 설정 구현 계획

사용자 승인 범위: 첨부 이미지와 유사한 차수별 매수 하락률·금액·익절률 입력, 일괄 적용 및 실제 자동매매 반영. 현재 세션에서 구현하고 자동 커밋하지 않는다.

화면과 동작

밝은 회색 행에 차수, 매수 기준, 매수금액, 매도 기준을 배치한다. 1차는 최초 진입으로 표시하고 익절률 기본값 10%를 유지한다. 숫자는 우측 정렬, 매수 기준은 파랑, 매도 기준은 빨강으로 표시한다. 기존 시스템 글꼴과 다크 모드를 사용한다. 작은 화면에서는 행 내부를 접어 배치한다.

관리 차수는 신규 전략에서 1~50차. 일괄 설정은 동일 금액·누적 배수·일정 금액 증가 방식으로 금액을 채우고 2차 이후 비율을 채운다. 1차 익절률은 개별 입력값을 유지한다. 각 행에서 최종 수정한 값이 저장된다. 기존 전략은 차수 개수를 유지하며 실행 중 또는 일시정지 상태에서 수정·저장할 수 있다. 저장은 실행 상태를 바꾸지 않는다.

구현 순서와 검증

  1. 차수별 설정 타입과 유효성 검사, JSON 저장 필드 추가. 기존 NULL 설정은 기존 공통 규칙으로 계산한다. 검증: 기존 방식, 개수·범위·통화 정밀도·합계·손상된 JSON 검사.
  2. 생성·수정·워커·화면 목표가를 동일한 차수 설정으로 연결한다. 수정은 active/paused 상태에서 lease 및 status/revision 확인 후 저장한다. 기존 주문은 보존하며 미확정 주문 정산 후 새 설정으로 판단한다. 검증: 저장 재조회, 실제 워커 경로를 가짜 브로커로 검증, 재진입 및 수정 거절 조건.
  3. TrancheEditor를 신규·기존 전략에 연결한다. 일괄 적용과 개별 수정, 차수 변경, 금액 부족 상태를 확인한다. 검증: 타입·린트·전체 테스트, 데스크톱·390px 모바일 브라우저 확인.
  4. DB 백업 후 additive migration 적용, 웹·워커 재시작과 기존 설정 보존 확인.

파일 경계

budget.ts: 예산 선택. tranche-settings.ts: 설정 생성·검증·파싱. live-rules.ts: 차수별 매수·매도 판단. live-run.ts: DB 생성·수정·워커. split-live.ts: 액션과 조회. TrancheEditor.tsx: 공통 편집 UI. LiveManager.tsx: 화면 연결. Prisma schema와 새 migration: nullable JSON 문자열.

검토 초점

배열 길이와 차수 불일치, 1차 기본값 및 기존 전략 보존, 일괄 적용과 개별 수정 우선순위, 미체결 주문 가격·수량 보존, 실제 잔액 부족 시 수량 제한, 이전 차수 매수가 기준 하락률, 재진입 generation과 slot 구분을 검증한다. 시장가 전환·매수매도 토글은 이번 UI 범위에 포함하지 않는다.

구현 결과 · 2026-10-31

구현 및 실제 웹·워커 반영 완료. 전체 59개 테스트 파일, 608개 테스트 통과. TypeScript 검사, 변경된 10개 TypeScript 파일 린트 통과. 독립 검토에서 발견한 시작 확인문 금액 불일치를 수정했다.

브라우저에서 관리 차수 변경, 기본 1차 익절률 10%, 일괄 금액 20만·30만·40만원, 일괄 적용 시 1차 익절률 유지, 이후 2차 익절률만 개별 변경을 확인했다. 1280px 및 390px 화면에서 가로 넘침이 없다. 실제 전략을 수정하거나 테스트 주문을 제출하지 않았다.

DB 백업: /private/tmp/company-map-before-tranche-settings-20261031.db. 마이그레이션 이후 기존 4개 전략의 설정·상태가 동일하고 새 JSON 필드가 NULL임을 대조했다. 웹 서버와 워커 재시작 후 단일 실행 잠금과 감시 시각 갱신을 확인했다.

LIVE 실행 중 수정 확장 · 2026-10-31

사용자 요청에 따라 실행 중에도 차수별 설정 저장을 허용했다. 기존 주문은 유지하고 다음 신규 주문 판단부터 적용한다. 저장 중 워커 실행은 lease로 배제하고 동시 일시정지·상태 변경은 status/revision 비교로 검출한다. 종료 전략은 수정할 수 없다.

관련 10개 파일의 171개 테스트와 타입·변경 파일 린트 통과. 가짜 브로커로 미체결 주문 보존과 새 매수 조건 반영을 검증하고, 실제 LIVE 전략에서 편집 UI가 열리는 것을 확인했다. 실제 전략 값 변경이나 검증용 주문은 실행하지 않았다. 독립 코드 검토에서도 추가 결함을 발견하지 못했다.
