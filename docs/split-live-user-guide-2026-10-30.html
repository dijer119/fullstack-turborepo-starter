분할매매 자동 실거래 사용법

2026-10-30 · company-map

분할매매 열기 · 공통 메뉴 ☰ → 도구 → 분할매매. 자동 실거래와 모의 장부는 각각 독립된 자금·체결 기록을 사용한다.

개발 중 실제 주문을 보내거나 실거래 전략을 시작하지 않았다. 운영 worker도 재시작하지 않았다. 새 루프를 사용하려면 변경된 코드를 읽는 worker를 사용자가 실행하고, 화면에서 계좌와 자금을 정해 자동매매를 시작해야 한다.

시작 순서

  1. 기존 토스 API 설정을 사용한다. 추가 서비스 가입이나 새 자격증명을 요구하지 않는다.
  2. 실거래 전략 만들기 → 토스 계좌 불러오기에서 일반 위탁계좌를 선택한다.
  3. 국내/미국 시장, 종목코드, 배정 자금, 차수 예산, 최대 차수, 하락 간격, 익절률, 비용 여유율을 정한다. 국내는 KRW, 미국은 USD이다. 기존 보유가 없는 종목으로 시작한다.
  4. 실거래 전략 저장 · 주문 없음으로 정지 상태의 새 장부를 만든다. 모의 장부를 실거래로 바꾸거나 기존 보유를 가져오지 않는다.
  5. 변경된 코드를 읽는 worker를 실행한다. 기존 프로세스가 있으면 중복 실행하지 않고 정리한 뒤 실행한다. 이 worker는 기존 DCA·무한매수 등 다른 루프도 함께 실행하므로 해당 전략들의 기존 실행 상태도 적용된다.
  6. 자동매매 시작·재개에서 계좌·종목·예산을 확인하고 시작한다. 정규장 또는 국내 NXT 애프터마켓의 첫 유효 시세에 1차 매수 주문을 낸다. 거래 가능 시간 중이면 다음 감시 때 시작한다. 
yarn --cwd /Users/dijer/dev/workspace/fullstack-turborepo-starter workspace company-map worker

worker:once는 연속 실거래 감시 루프를 실행하지 않는다. 위 worker 시작 명령은 이번 개발 과정에서 실행하지 않았다.

국내 애프터마켓 (2026-10-30 추가)

국내 전략은 NXT 지원이 확인되고 NXT 거래정지 상태가 아닌 종목에 한해 애프터마켓에서도 동일한 차수별 매수·매도 조건을 적용한다. 토스 캘린더의 애프터마켓 시작과 NXT 시가단일가 종료 시각을 모두 지난 후부터 종료 시각 직전까지 감시한다. 일반적인 접속매매 시간은 15:40~20:00이지만 실제 응답을 기준으로 판단한다. NXT 정보 또는 단일가 종료 정보가 누락되면 장후 주문을 보내지 않는다. 미국은 정규장만 사용하며 프리마켓·KRX 시간외종가·시간외단일가 거래를 추가하지 않았다.

적용하려면 기존 워커를 종료한 뒤 한 번 다시 시작해야 한다. 활성 국내 전략에는 이 정책이 적용된다. DB 변경은 필요 없다. 이번 구현에서는 워커 재시작이나 실제 주문 전송을 수행하지 않았다.

근거: 토스 공식 API 명세의 StockInfo.koreanMarketDetail, AfterMarketSession, OrderCreateRequest. 주문 본문은 기존 정수주 LIMIT/DAY를 사용하며 별도의 거래소 지정 인자는 없다. 실제 접수·체결 여부는 토스 주문 결과로 확인한다.

누적 수익금

실거래·모의 장부 상단에는 전체 전략의 누적 수익금을 원화와 달러로 나누어 표시한다. 전략별 기존 실현손익도 누적 수익금으로 표시한다. 장부에 반영된 매도 체결분의 순손익이며 수수료·세금과 손실을 반영한다. 종료한 전략과 이전 재진입 회차를 포함하고 보유 평가손익은 포함하지 않는다.

누적 수익금 표시는 기존 장부의 계산값을 재사용한다. 표시 변경에 따른 DB 변경이나 worker 재시작은 필요하지 않다. 통화별 집계와 손실 반영 테스트, 분할매매 관련 62개 테스트·앱 타입 검사·변경 파일 lint를 통과했다.

매매·장부 규칙

항목 동작
감시·주문 정규장과 국내 NXT 애프터마켓에 30초 간격의 REST 폴링. 정수주 지정가 DAY이며 시장가 추격·소수점 매매·자동 환전은 하지 않는다. 여러 전략이나 조회 지연이 있으면 간격이 늘어날 수 있다.
매수 1차는 시작 후 첫 시세에서 진입한다. 이후에는 보유 중인 직전 차수의 실제 평균 매수가 대비 설정 하락률을 사용한다. 비용 여유액을 포함해 배정 잔액과 실제 주문 가능 금액을 확인한다.
매도 차수별 익절 조건을 우선한다. 여러 차수의 조건이 겹치면 높은 차수부터 처리한다. 미해결 주문은 한 건만 유지하므로 모의 장부처럼 여러 차수를 한 관측에서 전량 체결시키지 않는다.
재진입·종료 하위 차수를 청산했고 직전 차수가 보유 중이면 조건에 따라 새 회차로 재진입한다. 모든 차수의 매도 체결과 비용이 정산되면 자동 감시를 유지하고, 다음 감시에서 같은 설정으로 새 1차를 매수한다. 차수당 예산은 그대로이며 기존 체결·수익금·현금 잔액은 유지한다. 1차 장부는 1차 2회, 1차 3회처럼 누적된다. 미체결·비용 미확정·일시정지·신규 주문 차단 중에는 재매수하지 않는다. 거래 시간·최신 시세·실보유·주문 가능 금액도 매번 다시 확인한다.
부분 체결 주문 접수는 체결이 아니다. 실제 누적 수량·금액·수수료·세금에서 이미 반영한 값을 뺀 차이만 저장한다. 부분 매도는 원가를 비례 배분한다. null 비용은 확정 0으로 처리하지 않고 정산을 보류한다.
운용 자금 배정 잔액은 전략의 운용 장부이며 토스 계좌에서 돈을 따로 예약하지 않는다. 예수금을 다른 용도로 사용하면 이후 주문 가능 금액이 부족할 수 있다. 비용 여유율은 실제 수수료·세율을 뜻하지 않는다.
가격·기간 매수 지정가는 호가 단위로 내리고 매도 지정가는 올린다. 현재 거래 세션 종료·시세 60초·실행 잠금 중 가장 이른 시각까지만 전송한다. OAuth 대기와 인증 재시도 뒤에도 HTTP 직전에 다시 검사한다.

전량 익절 후 자동 재시작 (2026-10-30 추가)

실거래는 전량 익절 후 같은 전략 안에서 반복한다. 10,000원에 10주를 매수하고 11,000원에 전량 매도했다면, 정산한 감시에서는 새 주문을 보내지 않고 다음 감시의 유효 시세를 기준으로 1차 매수를 계산한다. 수익금이 생겨도 차수당 예산을 자동으로 늘리지 않으며, 원래 배정 자금으로 잔액을 초기화하지 않는다. 누적 수익금은 모든 회차의 실제 비용을 반영한 실현손익 합계다.

반복을 멈추려면 신규 주문 일시정지를 누른다. 보유와 미해결 주문이 모두 없을 때 일시정지 후 보유 없는 전략 종료로 마칠 수 있다. 이전에 종료한 전략은 자동으로 되살리지 않는다. 모의 장부는 기존의 전량 청산 후 종료 방식을 유지한다.

코드를 적용하려면 기존 워커를 종료한 뒤 한 번 재시작한다. 실행 중인 전략에는 새 반복 규칙이 적용된다. DB 변경은 필요 없으며 구현 과정에서 운영 워커 재시작·전략 시작·실제 주문 전송은 수행하지 않았다.

검증: 전체 56개 파일의 520개 테스트, 앱 타입 검사, 변경 파일 lint 통과. 임시 SQLite와 가짜 브로커로 다음 감시 재진입·동시 호출·재시작·누적 손익·두 번의 익절·일시정지·수동 종료·장 마감·시세 지연·가용금액 부족·비용 미확정을 확인했다.

일시정지와 문제 해결

  • 신규 주문 일시정지: 새 주문을 멈춘다. 이미 접수된 주문은 체결될 수 있다. 취소·정정은 토스 앱에서 처리하고 주문 상태를 동기화한다.
  • 주문 상태만 동기화: 새 주문을 내지 않고 기존 주문·체결만 읽는다. 별도로 실행 중인 worker의 상태는 바꾸지 않는다.
  • 접수 결과 미확인: 타임아웃·응답 저장 실패는 자동 재전송하지 않는다. 토스에서 확인한 주문번호를 입력하면 계좌·종목·방향·수량·지정가·시각을 검증해 연결한다. 동기화와 장부 확인 후 재개한다.
  • 미접수 확인 기록: 토스 주문·체결 이력에서 접수되지 않았음을 직접 확인한 경우에만 사용한다. 이미 주문번호가 연결된 주문은 이 기능으로 해제할 수 없다.
  • 보유 불일치·다른 전략: 같은 계좌·종목의 다른 자동매매나 미체결 주문이 있거나 실잔량과 장부가 다르면 신규 주문을 막는다. 해당 종목의 수동 매매와 섞어 운용하지 않는다.
  • 비용·상태 미확정: 비용 null, 알 수 없는 상태·정정 주문은 보류 사유를 확인한다. 값이 확인된 뒤 동기화하고 재개한다.
  • 빈 전략 종료: 일시정지 중 보유와 미해결 주문이 모두 없을 때 종료하고 종목 관리 권한을 반납할 수 있다.
  • 전체 신규 주문 중지: 앱과 worker 환경의 SPLIT_LIVE_DISABLED=1을 사용한다. 기존 주문 동기화는 계속한다. 미체결 취소를 대신하는 설정은 아니다. 새 분할매매 루프는 worker 종료 신호에도 신규 주문을 중지한다.

차수별 예산 방식

새 실거래 전략은 최대 10차·동일 금액·1배가 기본이다. ‘1차 예산’과 ‘예산 방식’을 입력하고, 증가 방식에서는 ‘예산 배수 (2차 ÷ 1차)’를 설정한다. 기존 전략은 동일 금액·1배로 유지한다.

방식계산식1차 10만원 · 배수 2
동일 금액1차 예산10만 → 10만 → 10만
누적 배수1차 예산 × 배수^(차수−1)10만 → 20만 → 40만
일정 금액 증가1차 예산 × [1 + (차수−1) × (배수−1)]10만 → 20만 → 30만

차수별 예정 예산과 총 필요 자금을 입력 즉시 표시한다. 10차까지 누적 2배는 102,300,000원, 일정 증가는 5,500,000원이다. 배정 자금이 부족하면 저장할 수 없으며, 자금 입력은 자동으로 올리지 않는다. 증가 예산은 원·센트 단위로 내림하고 실제 수량은 비용 여유액을 포함해 정수주로 계산한다. 배수 1과 기존 동일 금액의 저장 정밀도는 유지한다.

익절한 3차를 다시 매수하면 동일한 3차 예산을 사용한다. 전량 익절 후에는 원래 1차 예산부터 재시작하며 회차 수나 누적 수익금에 배수를 추가 적용하지 않는다. 예산 방식과 배수는 전략 목록 및 실거래 시작 확인에도 표시된다. 모의 장부의 예산 설정은 기존 동일 금액 방식이다.
