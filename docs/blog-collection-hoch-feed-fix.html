blog-collection Atom 피드 인식 수정

검증일: 2026-11-04 (한국시간). hoch.io 피드를 실행 중인 앱에서 조회해 HTTP 200과 글 17개 반환을 확인했다.

원인과 수정

외부 서버는 정상 XML을 반환했지만 문서가 Atom의 <feed> 형식이었다. 기존 src/lib/rss/parser.ts의 parseRssFeed는 rss.channel만 찾고, 없으면 Invalid RSS feed: no channel found를 던졌다. 등록 API가 이 예외를 HTTP 400으로 반환해 구독 저장 전에 실패했다.

공통 파서에 Atom 변환 분기를 추가했다. HTML 페이지 링크, 글 ID, 본문, 작성자, 발행일 또는 수정일, 분류와 썸네일을 기존 데이터 형식으로 변환한다. 등록 API와 수집 코드가 같은 파서를 사용하며 기존 RSS 분기는 유지했다. 링크 관계와 날짜 구분은 Atom 표준 RFC 4287을 참고했다.

범위와 재실행

구현 변경은 공통 파서 한 파일이다. 기존 테스트가 없어 Node 내장 테스트로 회귀 검사를 추가했으며 별도 의존성은 추가하지 않았다. 이 테스트는 파싱 계약을 검사하며 네트워크와 DB 저장을 검사하지 않는다. 실제 구독 추가·DB 저장·Telegram 알림은 실행하지 않았다. 모든 Atom 변형의 지원을 보장하는 변경은 아니며 해당 피드의 기본 네임스페이스와 HTML 본문 형식을 검증했다.

node --experimental-strip-types --test /Users/dijer/dev/workspace/fullstack-turborepo-starter/apps/blog-collection/src/lib/rss/parser.test.mjs

테스트 명령은 TypeScript 제거 실행을 지원하는 Node가 필요하며 이번 검증은 Node v26.8.2에서 수행했다. 기존의 다른 작업을 보존하고 수정 범위만 수동 검토했다. 관련 없는 리팩터링·자동 커밋·배포는 수행하지 않았다.
