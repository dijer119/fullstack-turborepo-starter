1. 한눈에 보기

Matt Pocock(Total TypeScript)이 매일 쓴다는 에이전트 스킬 모음입니다. GSD·BMAD·Spec-Kit처럼 프로세스 전체를 쥐는 방식에 반대하고, 작고 조합 가능한 스킬을 표방합니다. 해결하려는 실패 유형은 네 가지입니다.

실패 유형처방대표 스킬
에이전트가 원하는 걸 안 만든다 (정렬 실패)구현 전 집요한 인터뷰grill-me, grill-with-docs
에이전트가 장황하다프로젝트 공용 용어집 CONTEXT.md + ADRdomain-modeling, grill-with-docs
코드가 안 돈다피드백 루프 (red-green-refactor, 재현 루프)tdd, diagnosing-bugs
진흙 덩어리가 된다deep module 설계 (Ousterhout)improve-codebase-architecture, codebase-design

스킬은 User-invoked(사용자가 /이름으로만 호출, disable-model-invocation: true, 오케스트레이션 담당)와 Model-invoked(에이전트가 상황을 보고 자동으로 부름, 재사용 규율 담당)로 나뉩니다. User-invoked 스킬이 Model-invoked 스킬을 부르는 구조이고, User-invoked끼리는 서로 부르지 않습니다.

4. 현재 환경과 겹치는 부분

이미 superpowers, compound-engineering, 내장 스킬이 켜져 있어서 기능이 상당 부분 겹칩니다.

mattpocock이미 있는 것차이
tddsuperpowers:test-driven-development거의 같은 역할. 둘 다 Model-invoked라 자동 호출 경합 가능
diagnosing-bugssuperpowers:systematic-debugging, ce-debug재현 루프 우선이라는 점은 같음. 세 번째 디버깅 스킬이 됨
code-review내장 code-review, ce-code-review, superpowers:requesting-code-reviewSpec 축(원 이슈 대비 충실도)을 따로 분리한 점이 차별점. 이름이 내장 스킬과 같아 mattpocock-skills:code-review로 구분해 불러야 함
grill-me / grillingsuperpowers:brainstorming, ce-brainstormbrainstorming은 설계안 제시까지 가고, grilling은 질문만 집요하게 함
to-spec / to-tickets / implementsuperpowers:writing-plans / executing-plans, ce-plan / ce-work산출물이 로컬 plan 파일이 아니라 이슈 트래커의 티켓
handoffce-handoff, session-summary, recall 플러그인같은 기능. 임시 디렉터리 저장이라 저장소에 안 남음
prototypece-prototype유사
research—1차 출처 한정·인용 필수 백그라운드 조사. 결과가 Markdown이라 HTML 문서 규칙과 충돌
domain-modeling / grill-with-docs— (직접 대응 없음)새로운 기능. CONTEXT.md 용어집 + ADR 누적. 이 저장소처럼 도메인 용어(T, cashKrw, stateApplied, 전일종가 규칙…)가 많은 곳에 맞음
improve-codebase-architecture / codebase-designsc:analyze, ce-simplify-code 일부deep module 관점의 정기 점검은 기존에 없음
wayfinder—여러 세션짜리 결정 지도. GitHub Issues 사용이 전제

5. 도입 시 주의할 점

  • 자동 호출 경합: Model-invoked 스킬 12개가 superpowers·compound-engineering의 비슷한 스킬과 같은 상황에서 경쟁합니다. 어떤 스킬이 불릴지 예측하기 어려워지고, 스킬 목록이 커질수록 컨텍스트도 더 씁니다.
  • implement는 끝에 자동 커밋합니다. "명시적 요청 없이 자동 커밋하지 말 것"이라는 CLAUDE.md 규칙과 충돌합니다. (User-invoked라서 부를 때만 동작하긴 합니다.)
  • 문서 형식 충돌: research·to-questionnaire·CONTEXT.md·ADR은 Markdown을 씁니다. "새 문서는 HTML" 규칙과 부딪히므로, 에이전트가 읽는 문서(CONTEXT.md, ADR)는 예외로 둘지 먼저 정해야 합니다.
  • 이슈 트래커 전제: to-spec·to-tickets·triage·wayfinder가 GitHub/GitLab Issues를 씁니다. 지금 이 저장소는 docs/*.html로 계획을 관리하므로, 쓰려면 로컬 .scratch/ 트래커를 고르는 편이 자연스럽습니다.
  • setup이 CLAUDE.md를 수정합니다(## Agent skills 섹션 추가, docs/agents/ 생성). 실행 전에 확인 절차가 있긴 합니다.
  • improve-codebase-architecture 리포트는 Tailwind·Mermaid를 CDN에서 불러옵니다. "외부 의존성 0" 규칙과는 맞지 않지만 임시 디렉터리에만 쓰는 파일이라 영향은 작습니다.

6. 추천

플러그인 전체 설치보다는 skills.sh로 골라 넣는 쪽을 권합니다. 이미 있는 기능과 겹치지 않고 새로 얻는 게 있는 것만 고르면 됩니다.
  1. grilling + domain-modeling + grill-with-docs: 기존 스킬에 없는 유일한 축입니다. company-map처럼 정정 이력이 많은 도메인 규칙(무한매수 T 정의, DCA 세 가드, 전일종가 산정)을 CONTEXT.md 용어집으로 모으면 지금 CLAUDE.md에 길게 붙은 서술을 줄일 수 있습니다.
  2. codebase-design + improve-codebase-architecture: 기존에 없는 정기 구조 점검입니다. company-map의 src/lib/ 핫스팟에 한 번 돌려볼 만합니다.
  3. git-guardrails-claude-code(misc): 필요하면 넣습니다. 다만 git push까지 막으므로 PR 흐름(ce-commit-push-pr)과 충돌합니다.
  4. 나머지(tdd, diagnosing-bugs, code-review, handoff, prototype, to-spec/tickets/implement)는 기존 스킬과 겹치므로 건너뛰는 것을 권합니다.

이 문서는 공개 저장소의 README와 SKILL.md 원문만 보고 정리했습니다. 실제로 설치하거나 실행해 보지는 않았습니다.
